# 현재 분석 지표와 전체 보관 이력

대시보드는 과거 증거와 현재 상태를 구분한다. 이전 SBOM이나 취약점 기록은 재분석 후에도 보존한다.

## API 지표

`GET /api/dashboard/summary`의 기존 최상위 `sbom_documents`, `components`, `dependencies`, `open_cves`, `affected_assets`는 **전체 보관 이력** 기준을 유지한다. `open_cves`는 해당 이력에서 VEX 상태가 `AFFECTED` 또는 `UNDER_INVESTIGATION`인 고유 취약점 수이다.

새 `current_inventory`는 현재 대상으로 선택한 SBOM만 사용한다.

| 필드 | 의미 |
| --- | --- |
| sbom_documents | 현재 대상으로 선택한 고유 SBOM 수 |
| components | 해당 문서의 구성요소 사용 위치 수 |
| dependencies | 해당 문서의 의존 관계 수 |
| assets | 해당 문서가 연결된 고유 자산 수 |
| open_cves | 해당 구성요소의 미해결 고유 CVE 수 |
| affected_assets | 해당 CVE가 연결된 고유 자산 수 |
| lifecycle_items | 아래 지원 종료 위험 계산에 포함된 항목 수 |

같은 CVE가 여러 구성요소·범위에서 검출되어도 고유 CVE 수에는 한 번만 센다. 구성요소 사용 위치 수와 자산 수는 다른 단위이다.

## 현재 SBOM 선택 규칙

1. 분석 결과는 **자산·분석 범위별 마지막 성공 결과**를 선택한다. 같은 시각이면 분석 ID가 큰 결과를 선택한다. 최신 작업이 실패·대기·취소 상태여도 마지막 성공 결과는 유지한다.
2. 분석 결과에 연결되지 않은 수동 import 문서는 **자산별 최신 수동 SBOM**을 별도 대상으로 포함한다. 같은 시각이면 SBOM ID가 큰 문서를 선택한다. 수동 문서에는 앱 경로 같은 분석 범위 식별자가 없으므로, 한 자산의 서로 다른 수동 앱 문서를 자동으로 구분하지 않는다.
3. 자산에 연결되지 않은 문서는 같은 프로젝트라고 추정할 수 없어 각 문서를 별도 대상으로 포함한다. 연결과 입력 범위를 명확히 지정해야 현재 상태의 범위도 명확해진다.

최신 성공 결과에서 CVE가 검출되지 않으면 현재 CVE 수는 줄어들 수 있다. 과거 이력의 CVE 상태를 자동으로 수정하거나 조치 완료로 판정하지 않는다.

## 지원 종료 위험의 공통 계산

대시보드 `lifecycle_risk`·`urgent_items`, 지원 종료 PDF, Teams 위험 요약 생성은 `services/lifecycle_overview.py`의 같은 계산기를 사용한다. Teams 전송은 기존의 명시적인 전송 요청에 의해서만 수행한다.

계산 대상은 다음과 같다.

- 관리 자산 각각.
- 현재 SBOM의 구성요소 사용 위치 각각.
- 현재 구성요소에 연결된 제품으로 이미 표현되지 않은 등록 소프트웨어. 단, 과거 SBOM에만 등장하는 제품은 제외한다. 명시적 `Deployment`가 있거나 구성요소 이력이 전혀 없는 직접 등록 제품은 포함한다.

따라서 재분석에서 사라진 구버전 패키지를 제품 카탈로그 항목으로 다시 더하지 않는다. 현재 구성요소와 그 구성요소의 제품 카탈로그도 중복으로 더하지 않는다. 소프트웨어를 별도로 배포 항목으로 관리하고 있다면 해당 배포의 제거·변경도 실제 관리 상태에 맞게 반영해야 한다.

구성요소의 종료일은 **개별 override → 제품 보안 지원 종료일 → 제품 일반 지원 종료일 → 제품 EOL** 순서로 선택한다. override를 비우면 제품 날짜를 다시 상속한다. 날짜가 없는 현재 구성요소는 `UNKNOWN`으로 센다. 자산의 제품 모델 날짜 우선순위는 기존 동작을 유지한다.

`aggregation_basis`에는 현재/전체 이력의 선택 기준, 위험 계산 단위, 기준 날짜, 설정된 업무 시간대가 들어 있다. 모든 항목은 한 번 정한 업무 날짜를 사용해 자정 전후에 날짜 기준이 섞이지 않도록 한다.

## 검증

집계·대시보드·업무 날짜·SBOM 탐색 focused 테스트 31개가 통과했다. 최신/수동/미연결 SBOM 선택, 구버전 카탈로그 재집계 방지, 직접 배포 유지, 제품 상속과 개별 override, 고유 자산/CVE 수, PDF와 요약 내용의 일치, 긴 PDF 행의 페이지 넘김, 원본 보고서 미조회·보존을 확인한다. 알림 생성 테스트는 전송 함수를 대체하며 외부 메시지를 보내지 않는다.

분석 이력 탐색과 EOL 관리 사용법은 [프로젝트 이력·EOL 안내](PROJECT_HISTORY_AND_EOL.md)를 참고한다.
