# 프로젝트 이력과 공개 EOL 일정

2026-09-16 추가 개발. 기존 ZIP·SSH 분석과 조치 기록 위에 장기 이력 탐색, 저장 입력 재사용, 취소, 공개 지원 일정 연결을 추가한다.

## 웹 사용 흐름

1. **작업 대상 → 프로젝트·결과**에서 자산을 선택한다. 조회자도 자산 상세와 결과에 접근할 수 있다.
2. **프로젝트·분석 이력**은 자산과 분석 범위별로 마지막 성공 결과·최근 요청·예약·ZIP 버전을 묶는다.
3. 분석 결과와 작업 이력을 날짜·자산·범위·상태로 찾는다. 서버에서 페이지를 나누므로 최근 100건 이전의 결과도 선택할 수 있다.
4. 서로 다른 페이지에서 이전·이후 분석을 선택해 비교하고 원본과 PDF·JSON을 내려받는다. 같은 자산·범위의 시간 순서가 맞는 결과를 선택한다.
5. 저장된 ZIP의 파일명·크기·SHA-256을 확인하고 **저장된 ZIP 재분석**을 실행한다. 새 작업은 기존 업로드 ID와 원본 해시를 사용한다.
6. 분석 결과에서 SBOM 구성요소와 CVE 화면을 오가고, 해당 자산의 조치 작업목록으로 이동한다. 조치 근거 후보도 과거 기준 분석에서 서버 조회한다.

기존 `/analyses`와 `/analyses/jobs`는 최근 100건 배열 응답을 유지한다. 새 전체 이력 화면은 별도 페이지 API를 사용한다. 활성 작업은 `/analyses/jobs/active`와 단건 조회로 추적하며 이력 페이지에서 밀려도 추적을 계속한다.

## 저장된 입력과 취소

- 같은 자산·프로젝트 이름·SHA-256의 ZIP 등록은 기존 입력을 재사용한다.
- 유효한 ZIP 보관과 작업 요청을 구분한다. 다른 작업 때문에 요청이 막히면 원본은 보관함에 남고 HTTP 409 안내 뒤 재분석할 수 있다.
- 목록의 `AVAILABLE`은 파일 존재·크기가 맞는 상태다. 다운로드와 재분석 시 SHA-256을 검증한다. 누락·변조·심볼릭 링크 원본은 거부한다.
- 관리자 보관 현황은 파일 수·바이트·디스크 여유·미참조·누락·크기 불일치·임시 파일을 보여준다. 전체 내용을 검증한 결과로 표시하지 않는다.
- 대기 취소는 즉시 `CANCELLED`. 실행 중 취소는 `CANCEL_REQUESTED` 상태로 자산 잠금을 유지하고 프로세스 종료 확인 후 `CANCELLED`가 된다. 저장 트랜잭션이 먼저 완료되면 취소는 409를 반환한다.
- 워커 중단 뒤 종료 확인이 없으면 잠금을 임의 해제하지 않는다. [취소 운영 안내](ANALYSIS_CANCELLATION.md)를 따른다.

파일시스템과 DB 사이에 완전한 단일 트랜잭션은 없다. 파일 보관 직후 프로세스가 강제 종료되면 미참조 파일이 남을 수 있어 보관 현황에 드러내며, 기존 원본 자동 삭제는 수행하지 않는다.

## 공개 지원 일정 연결

**EOL 일정 조회**에서 등록 제품 → 공개 제품 → 지원 주기를 선택한다. 공개 목록과 선택한 공개 제품 URL만 조회하며 자산 이름·프로젝트 내용·설치 버전 목록을 외부로 전송하지 않는다.

| 정보 | 의미 |
|---|---|
| 일반 기능 지원 종료 | 제공처의 `eoasFrom` |
| 표준 지원 종료 | 보안 수정을 포함한 `eolFrom`; 확정 날짜를 제품 `security_end_date`에 적용 |
| 연장 지원 | `eoesFrom`; 별도 계약 조건을 확인해야 하며 이 작업으로 적용하지 않음 |
| 수동 입력 시각 | 사람이 기존 날짜/URL을 저장한 시각; 외부 내용을 검증한 시각이 아님 |
| 본문 수집·최근 조회 시각 | API 응답을 보관하거나 304 응답으로 다시 확인한 시각 |
| 제공처 생성·변경 시각 | 공개 응답에서 제공한 `generated_at`·`last_modified` |

날짜와 지원 주기를 이름만으로 자동 지정하지 않는다. 관리자가 제품·배포판·에디션과 주기를 확인한 뒤 미리보기의 기존 값/공개 값을 비교하여 적용한다. 제품 또는 카탈로그가 미리보기 이후 바뀌면 다시 비교해야 한다.

적용 이력은 선택한 제품·주기, 사용자, 이전·이후 값, 응답 원문과 SHA-256, API 출처와 공식 정책 URL을 보존한다. 구성요소의 개별 날짜는 유지된다. 종료 날짜 미확정, 조회 실패 또는 24시간이 지난 자료는 적용을 차단하고 이전 자료를 보존한다. `isMaintained`만 보고 일반 지원 중이라고 판정하지 않는다.

공급자 스키마와 필드 의미: [endoflife.date 공식 v1 OpenAPI](https://endoflife.date/docs/api/v1/openapi.yml).

## 새 조회 API

접두사는 `/api`다. 페이지 응답은 `items`, `total`, `limit`, `offset`을 포함한다.

| 경로 | 기능 |
|---|---|
| `GET /analyses/projects` | 자산·범위별 프로젝트; `asset_id`, `scan_scope`, `q`, 페이지 |
| `GET /analyses/history` | 모든 성공 분석; 자산·범위·검색·업무 날짜·페이지 |
| `GET /analyses/job-history` | 작업 이력; 동일 필터와 상태 |
| `GET /analyses/jobs/active` | 모든 활성 작업 |
| `GET /analyses/jobs/{id}` | 오래된 작업 단건 조회 |
| `POST /analyses/jobs/{id}/cancel` | 관리자 취소 요청 |
| `GET /analyses/runs/{id}` | 원본 JSON을 제외한 분석 메타데이터 |
| `GET /analyses/runs/{id}/candidates` | 같은 자산·범위의 이후 분석 후보와 기준 분석 |
| `GET /analyses/uploads` | 자산·범위별 입력 ZIP 페이지 |
| `GET /analyses/uploads/{id}/raw` | SHA-256 검증 후 원본 다운로드 |
| `POST /analyses/uploads/{id}/jobs` | 관리자 저장 입력 재분석 |
| `GET /analyses/storage` | 관리자 저장소 현황 |
| `GET /lifecycle-catalog/local-products` | 등록 제품 검색·페이지 |
| `GET /lifecycle-catalog/products` | 저장된 공개 제품 목록·검색 |
| `GET /lifecycle-catalog/products/{slug}` | 저장된 제품의 지원 주기·근거 |
| `POST /lifecycle-catalog/refresh` | 관리자 공개 목록/선택 제품 조회 |
| `GET /lifecycle-catalog/preview/{product_id}` | 선택한 공개 주기의 적용 전후 비교 |
| `POST /lifecycle-catalog/apply` | 관리자 명시적 적용·변경 충돌 검사 |
| `GET /lifecycle-catalog/applications` | 제품별 적용 이력 |

## 데이터 보존

마이그레이션 `a16c902bf743`은 `f8b319ac6402` 다음에 공개 카탈로그 캐시와 적용 이력 테이블을 추가한다. 과거 분석 원본·CVE 조치 이력·업로드 파일은 변경하지 않는다. 새 SBOM 가져오기는 PURL·버전·CPE 충돌을 검사하므로 잘못된 제품 연결로 다른 버전의 지원 일정을 상속하지 않는다. 과거 문서를 새 판단으로 일괄 재연결하지 않는다.

## 현재 위험과 누적 이력

대시보드의 현재 분석 지표는 자산·분석 범위별 최신 성공 SBOM, 자산별 최신 수동 반입 SBOM을 사용한다. 미연결 문서는 같은 프로젝트라고 추정하지 않고 개별 문서로 계산한다. 실패·취소 요청은 마지막 성공 결과를 대체하지 않는다.

지원 종료 분포·PDF·알림 내용 생성은 같은 계산기를 사용한다. 구성요소 개별 날짜를 우선하고 없으면 제품 날짜를 상속한다. 현재 구성요소로 표현한 제품을 카탈로그 항목으로 다시 세지 않으며, 과거 SBOM에만 남은 제품은 명시적 배포가 없으면 현재 위험에서 제외한다. 기존 최상위 문서 수·구성요소 수·미완료 CVE 수는 전체 보관 이력이다.

분석 범위는 각기 별도로 유지된다. 오래된 테스트 프로젝트 폴더도 그 범위의 마지막 결과로 남는다. 전체 자산이 지금 그 패키지를 실행 중이라고 판정하는 기능은 아니다.
