# 검사 이력·저장 ZIP·취소

2026-09-16 추가 개발분을 2026-09-21 기준으로 정리했다. 기존 ZIP·SSH 검사와 조치 기록 위에 장기 이력 탐색, 저장 입력 재사용, 취소를 제공한다. 같은 시기에 추가했던 공개 EOL 일정 연결 기능은 2026-09-18 재범위화에서 제거했다.

## 웹 사용 흐름

1. `검사 기록` → `검사 이력`에서 서버를 선택한다. 조회자도 결과에 접근할 수 있다. `인프라 검사`의 서버 행 `이력` 버튼으로도 이동한다.
2. 프로젝트 목록은 서버와 검사 범위별로 마지막 성공 결과·최근 요청·ZIP 버전을 묶는다.
3. 검사 결과와 작업 이력을 날짜·서버·범위·상태로 찾는다. 서버에서 페이지를 나누므로 최근 100건 이전의 결과도 선택할 수 있다.
4. 서로 다른 페이지에서 이전·이후 검사를 선택해 `검사 전후 비교`로 이동하고 원본과 PDF·JSON을 내려받는다. 같은 서버·범위의 시간 순서가 맞는 결과를 선택한다.
5. 저장된 ZIP의 파일명·크기·SHA-256을 확인하고 **저장된 ZIP 재검사**를 실행한다. 새 작업은 기존 업로드 ID와 원본 해시를 사용한다.
6. 검사 결과에서 `의존성 목록`과 `CVE 결과·조치` 화면을 오가고, 해당 서버의 조치 작업목록으로 이동한다. 조치 근거 후보도 과거 기준 검사에서 서버 조회한다.

기존 `/analyses`와 `/analyses/jobs`는 최근 100건 배열 응답을 유지한다. 전체 이력 화면은 별도 페이지 API를 사용한다. 활성 작업은 `/analyses/jobs/active`와 단건 조회로 추적하며 이력 페이지에서 밀려도 추적을 계속한다.

## 저장된 입력과 취소

- 같은 서버·프로젝트 이름·SHA-256의 ZIP 등록은 기존 입력을 재사용한다.
- 유효한 ZIP 보관과 작업 요청을 구분한다. 다른 작업 때문에 요청이 막히면 원본은 보관함에 남고 HTTP 409 안내 뒤 재검사할 수 있다.
- 목록의 `AVAILABLE`은 파일 존재·크기가 맞는 상태다. 다운로드와 재검사 시 SHA-256을 검증한다. 누락·변조·심볼릭 링크 원본은 거부한다.
- 관리자 보관 현황은 파일 수·바이트·디스크 여유·미참조·누락·크기 불일치·임시 파일을 보여준다. 전체 내용을 검증한 결과로 표시하지 않는다.
- 대기 취소는 즉시 `CANCELLED`. 실행 중 취소는 `CANCEL_REQUESTED` 상태로 서버 잠금을 유지하고 프로세스 종료 확인 후 `CANCELLED`가 된다. 저장 트랜잭션이 먼저 완료되면 취소는 409를 반환한다.
- 워커 중단 뒤 종료 확인이 없으면 잠금을 임의 해제하지 않는다. [취소 운영 안내](ANALYSIS_CANCELLATION.md)를 따른다.

파일시스템과 DB 사이에 완전한 단일 트랜잭션은 없다. 파일 보관 직후 프로세스가 강제 종료되면 미참조 파일이 남을 수 있어 보관 현황에 드러내며, 기존 원본 자동 삭제는 수행하지 않는다.

## 조회 API

접두사는 `/api`다. 페이지 응답은 `items`, `total`, `limit`, `offset`을 포함한다.

| 경로 | 기능 |
|---|---|
| `GET /analyses/projects` | 서버·범위별 프로젝트; `asset_id`, `scan_scope`, `q`, 페이지 |
| `GET /analyses/history` | 모든 성공 검사; 서버·범위·검색·업무 날짜·페이지 |
| `GET /analyses/job-history` | 작업 이력; 동일 필터와 상태 |
| `GET /analyses/jobs/active` | 모든 활성 작업 |
| `GET /analyses/jobs/{id}` | 오래된 작업 단건 조회 |
| `POST /analyses/jobs/{id}/cancel` | 관리자 취소 요청 |
| `GET /analyses/runs/{id}` | 원본 JSON을 제외한 검사 메타데이터 |
| `GET /analyses/runs/{id}/candidates` | 같은 서버·범위의 이후 검사 후보와 기준 검사 |
| `GET /analyses/uploads` | 서버·범위별 입력 ZIP 페이지 |
| `GET /analyses/uploads/{id}/raw` | SHA-256 검증 후 원본 다운로드 |
| `POST /analyses/uploads/{id}/jobs` | 관리자 저장 입력 재검사 |
| `GET /analyses/storage` | 관리자 저장소 현황 |

## 데이터 보존

ZIP 입력 보관과 정기 검사 예약 테이블은 마이그레이션 `f8b319ac6402`에서 추가했다. 그 뒤 `a16c902bf743`이 추가한 공개 EOL 카탈로그 캐시·적용 이력 테이블은 `d2f8c4a71e9b`에서 제거했다. 과거 검사 원본·CVE 조치 이력·업로드 파일은 변경하지 않는다.

## 현재 기준과 누적 이력

개요의 현재 기준 지표(`current_open_cves`, `current_affected_assets`)는 서버·검사 범위별 최신 성공 SBOM과 서버별 최신 수동 반입 SBOM을 사용한다. 미연결 문서는 같은 프로젝트라고 추정하지 않고 개별 문서로 계산한다. 실패·취소 요청은 마지막 성공 결과를 대체하지 않는다. 기존 최상위 문서 수·구성요소 수·미완료 CVE 수(`open_cves`)는 전체 보관 이력이다.

검사 범위는 각기 별도로 유지된다. 오래된 테스트 프로젝트 폴더도 그 범위의 마지막 결과로 남는다. 전체 서버가 지금 그 패키지를 실행 중이라고 판정하는 기능은 아니다.
