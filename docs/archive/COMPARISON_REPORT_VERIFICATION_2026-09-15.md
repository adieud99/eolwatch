# 분석 비교 보고서 실제 검증 — 2026-09-15

## 완료한 기능

웹 전후 비교 결과에서 **검증 보고서 PDF·검증 데이터 JSON**을 내려받을 수 있다. 기존 분석 #3 → #4로 실제 다운로드를 확인했다. 보고서는 자산·분석 범위·도구·DB 기준·설치 버전·CVE 변화·작업 시각·원본 해시·해석 조건을 포함한다.

사용 안내와 API·해시 형식: [COMPARISON_REPORTS.md](../COMPARISON_REPORTS.md).

## 실제 브라우저 동작

- 서비스: 관리 VM의 <http://127.0.0.1:18080>
- 화면: `CVE 조치` → `분석 전후 비교` → 이전 #3 / 이후 #4
- 대상: LAB-VM-01 / `demo-python-venv`
- 두 버튼을 실제로 클릭하고 Chrome의 다운로드 완료 이벤트와 저장 파일을 확인했다.
- 파일명·PDF 형식·JSON의 분석 ID·요약·CVE·해시·해석 조건이 기대한 값과 일치했다.
- 브라우저 실행 오류 0건, 실패한 API 요청 0건이었다.
- 이 검증의 쓰기 요청은 로그인뿐이었다. 작업 ID는 기존 #1·#2·#3으로 유지됐고, SBOM #12의 과거 CVE 세 건은 수동 VEX `AFFECTED`를 유지했다.

## 자동 검증

- 백엔드 **97개 통과**. 보고서 관련 신규 8개 검사는 로그인·조회자 권한, 비교 조건 거부, 원본 해시 불일치 거부, 전체 121행 JSON 수록, 자산명 변경 시 작업 스냅샷 사용, 수동 반입 주의사항, 민감한 실행 설정 제외, 상태 변경 없음과 PDF 글꼴 포함을 확인했다.
- 프런트엔드 **27개 통과**. 표시 중인 분석 쌍의 다운로드, 인증 헤더·파일명·Blob 처리, 중복 클릭 방지, 오류 후 재시도, 선택 변경·화면 종료 시 오래된 다운로드 취소, 조건 차이가 있을 때의 보고서 제공을 확인했다.
- 두 Docker 환경에서 최종 빌드와 배포가 완료됐고 `18080/health`, `8080/health`가 정상 JSON을 반환했다.
- PDF 생성기에 긴 한글 이름·12,000자 식별자·HTML처럼 보이는 문자열을 포함한 40행을 제공해 14페이지로 출력했다. 마지막 행까지 추출됐고 외부 링크·이미지 주석은 없었다. 원본 문자열을 문서 내용으로 처리하며 외부 URL을 조회하지 않는다.
- 실제 내려받은 PDF **3페이지 전체**를 확인했다. 한글·CVE 세 행·다섯 해시·여섯 해석 조건·작업 시각이 보존됐고 잘림·겹침이 없었다. JSON과 PDF는 별도 요청으로 생성돼 생성 시각은 다르지만 분석 근거는 같다.

- `reports/demo-verification-report-download.png`: 실제 다운로드 버튼과 비교 결과 화면
- `/private/tmp/eolwatch-analysis-report-download-check.json`: Chrome 다운로드·요약·오류·요청 검증 기록
- `reports/comparison-report-pages/`: 실제 PDF 페이지 미리보기

`reports/`는 Git에서 제외되는 로컬 검증 자료다. 교수님께 설명할 흐름은 [REMEDIATION_DEMO.md](../REMEDIATION_DEMO.md)의 업데이트 시연 뒤에 보고서 다운로드를 붙이면 된다.
