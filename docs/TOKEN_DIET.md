# AI 토큰 다이어트 — 발표용 정리

EOLWatch는 AI를 세 곳에서 쓴다(검사 결과·SSH 점검 요약, 잠금 파일 없는 소스의 라이브러리 참조, SSH 점검의 수집 에이전트). 모두 유료 토큰을 쓰므로 "보내는 양·받는 양·부르는 횟수"를 각각 줄였다. 아래 숫자는 2026-09-21~22에 실제 서버(srv-han EC2, 시연 소스)로 측정한 값이다.

## 1. 결과

| 요청 | 다이어트 없이 | 다이어트 후 | 비고 |
|---|---|---|---|
| 검사 결과 요약 (CVE 61개 검사) 입력 | 14,432자 (CVE 61행 전체) | **2,550자 (약 1,050토큰)** | 82% 감소 |
| SSH 점검 요약 입력 | 서버 정보 + 설치 패키지 679개 = 약 38,000자 | **1,608자 (약 780토큰)** | 패키지는 건수만 |
| 같은 요약의 총 토큰 (숨은 추론 포함) | 1,651토큰 | **260토큰** | 추론 끔, 84% 감소 |
| OS 검사(CVE 5,359개, 연결 35,125건) 요약 입력 | 약 830만 자 (보낼 수 없는 크기) | **약 2,500자** | 상한이 있어 규모와 무관 |
| 수집 에이전트 명령 선택 입력 | — | 1,329자 (약 630토큰), 같은 환경은 재사용 | 카탈로그 17개 id·목적만 |
| 라이브러리 참조 입력 | 소스 전체 | 약 500토큰 (import 이름 + 의존성 파일 앞부분) | 시연 소스 기준 |

핵심 한 줄: **요약 한 번에 300~1,000토큰, 숨은 추론을 끄면 총 토큰이 6분의 1.** 무료 등급에서는 토큰보다 "하루 요청 횟수"가 먼저 걸릴 만큼 작다.

## 2. 방법

### 2-1. 보내는 데이터를 압축한다 (입력 토큰)
- **CVE는 라이브러리별로 묶는다.** 같은 라이브러리의 CVE 수십 개를 한 줄로: 최고 심각도, 건수, 수정 버전(3개까지), 대표 CVE 2개(설명 60자). 라이브러리는 심각도 순 15개까지, 나머지는 "생략 n개"로만 알린다. (`ai_advisor.analysis_context`)
- **서버 정보는 상한을 둔다.** 포트 15, 서비스 12, 프로세스 5, 디스크 4, 에이전트 출력 8건×160자. 설치 패키지 수백 개는 건수만 보낸다. (`ai_advisor.check_context`)
- **JSON은 공백 없이, 한글은 그대로.** `separators=(",", ":")`, `ensure_ascii=False`. 이스케이프된 한글은 토큰을 3~4배 먹는다. (`ai_advisor._dumps`)
- **키 이름을 짧게.** `lib`, `ver`, `n`, `max`, `fix`처럼 줄이고 뜻은 시스템 프롬프트에 한 번만 적는다.
- **수집 에이전트에는 명령 문자열을 보내지 않는다.** 카탈로그의 id와 목적만 보여 주고 id를 고르게 한다. 명령은 서버 쪽 허용 목록에서만 실행되니 보안과 토큰을 같이 아낀다. (`ai_collection.catalog_for`)
- **라이브러리 참조는 소스를 보내지 않는다.** import 이름(생태계별 60개, 표준 라이브러리·자체 모듈 제외)과 의존성 파일 앞부분(6개, 1,500자)만 보낸다. (`ai_library_reference.gather_evidence`)

### 2-2. 받는 양을 통제한다 (출력 토큰)
- **숨은 추론(thinking)을 끈다.** Gemini 2.5·GPT-5 계열은 답 앞에서 "생각"을 하고 그 토큰도 출력처럼 과금한다. 기본으로 `reasoning_effort=none`을 보내고, 값을 거부하는 모델에는 자동으로 빼고 다시 보낸다. 측정: 같은 요청 1,651 → 260토큰. (`OPENAI_REASONING_EFFORT`)
- **답 길이를 프롬프트로 제한한다.** "600자 안, 마크다운 없이, 목록 3~5개." 출력 상한은 잘림 방지용 여유만 준다.

### 2-3. 부르는 횟수를 줄인다
- **같은 데이터·같은 모델이면 저장된 답을 재사용한다.** 프롬프트의 SHA-256을 저장해 두고 일치하면 AI를 부르지 않는다. "다시 생성"을 눌렀을 때만 새로 부른다. (`ai_advisor.generate_summary`)
- **수집 에이전트는 환경이 같으면 답을 재사용한다.** OS·아키텍처·플랫폼·포트·서비스가 같은 서버는 프로세스 안에서 한 번만 묻는다. (`ai_collection._plan_cache`)
- **AI가 필요 없는 경우는 아예 부르지 않는다.** 잠금 파일이 있으면 라이브러리 참조를 건너뛰고, 과부하(503)·한도(429)면 짧게 재시도한 뒤 OS 규칙으로 대체해 검사 자체는 끝낸다.

## 3. 확인하는 방법
- 요약 카드 아래에 "입력 n 토큰 / 출력 m 토큰 (압축한 데이터 k자)"가 남는다. `ai_summaries` 표에도 같은 값이 저장된다.
- 검사 작업의 `manifest.json`에 라이브러리 참조의 `prompt_chars`·토큰이, SSH 점검의 `server_info.ai_collection`에 에이전트의 토큰이 남는다.

## 4. 발표 문장 예시
"AI에는 저장된 검사 데이터만 보내되, CVE 5,359개짜리 결과도 라이브러리 15개·대표 CVE 2개로 압축해 약 2,500자로 보냅니다. 모델이 몰래 쓰는 추론 토큰을 끄니 같은 요약의 총 토큰이 1,651에서 260으로 줄었고, 같은 데이터는 저장된 답을 재사용해 다시 부르지 않습니다."
