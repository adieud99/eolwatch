Terraform 실행 결과는 리소스 20개 생성, 변경 0개, 삭제 0개다. S3 버킷은 공개 접근 차단, AES-256 서버 측 암호화, `postgres/` 경로 7일 만료 정책을 적용했다. 서비스 서버는 80·443만 공개하며 운영 접속에는 SSH 포트를 열지 않고 SSM을 사용한다. 점검 대상의 SSH 포트는 서비스 보안그룹에서만 접근할 수 있다.

## 현재 검증 상태

- 네 EC2 인스턴스가 AWS 상태 검사를 통과했다.
- 네 EC2 인스턴스가 SSM Online 상태다.
- Elastic IP를 가리키는 임시 DNS 조회가 성공했다.
- 운영 소스 묶음에서 `.git`, `.venv`, `node_modules`, 빌드 결과, Terraform 상태, SSH 키와 `known_hosts` 제외를 확인했다.

## 남은 배치 단계

1. 검토된 소스 묶음을 전용 비공개 S3 버킷의 `deployment/` 경로에 업로드한다.
2. SSM으로 서비스 서버에 압축을 풀고 운영 비밀값을 서버 내부에서 생성한다.
3. 서비스 서버에서 수집용 SSH 키를 생성하고 공개키만 점검 대상 3대에 설치한다.
4. 서비스 서버에서 점검 대상 호스트 키를 수집해 `known_hosts`를 만든다.
5. 운영 Compose를 빌드·기동하고 Caddy HTTPS 인증서를 확인한다.
6. 합성 데이터를 대상 EC2 사설 IP로 연결한 뒤 점검과 SBOM 생성을 실행한다.
7. PostgreSQL 백업을 S3에 올리고 별도 임시 DB로 복구 검증한다.

Terraform 상태 파일에는 인프라 식별정보가 들어 있으므로 Git에 커밋하지 않는다.
