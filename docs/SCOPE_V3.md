# EOLWatch 현재 범위

코드 기준: 2026-09-15 기능 확장. 실제 배포·실행 근거는 [확장 검증 기록](PROJECT_EXPANSION_VERIFICATION.md)을 따른다.

## 프로젝트 한 문장

**EOLWatch는 재고자산 원장에 SBOM 생성·취약점 분석 결과를 연결해 웹에서 자산별 소프트웨어 구성, CVE·지원 종료, 비용·계약과 조치 이력을 관리하는 서비스다.**

Black Duck과 같은 구성요소·취약점 관리 영역에 속하지만, 이번 프로젝트는 서버 자산에 분석 결과를 연결하고 운영자가 처리·재분석 근거를 관리하는 흐름에 집중한다. Black Duck 계정·서버·Detect 실행은 필수가 아니다. Black Duck 호환 SPDX 샘플은 형식 예제로 구분한다.

## 관리 앱과 분석 대상

- **관리 앱:** React 웹 + FastAPI + PostgreSQL + 분석 worker. 사용자는 브라우저로 작업한다.
- **분석 대상:** 등록된 Linux 서버의 OS·앱 디렉터리·Python 환경 또는 웹에 첨부한 소스 ZIP.
- **도구:** Syft 1.51.1로 구성요소 수집, SPDX 2.3 변환, Grype 0.118.0으로 같은 SPDX의 취약점 분석. 별도 OSV 조회도 지원한다.
- **실습 환경:** 관리 VM 1대, 대상 VM 2대. 관리 VM 웹은 `127.0.0.1:18080`이며 맥 개발 Docker의 `:8080`은 별도 DB다.

## 지원하는 입력

| 입력 | 읽는 대상 | 비교 범위 |
|---|---|---|
| 소스 ZIP | 포함된 패키지 명세·잠금 파일·설치 메타데이터 | 자산 + 프로젝트 이름 |
| 서버 프로젝트 폴더 | SSH 계정이 읽을 수 있는 절대 경로 아래의 구성요소 | 자산 + 프로필 + 정규화된 경로 |
| 서버 Python 가상환경 | 지정한 절대 경로의 설치 패키지 메타데이터 | 자산 + 프로필 + 정규화된 경로 |
| Ubuntu 설치 패키지 | dpkg 설치 패키지 | 자산 + Ubuntu 프로필 |
| 기존 Python 데모 앱 | `~/eolwatch-demo/.venv` | 자산 + 데모 프로필 |
| 기존 SBOM/분석 묶음 반입 | SPDX 2.3, CycloneDX 1.4~1.7, SPDX+Grype JSON | 원본에 기록한 자산·범위와 반입 이력 |

ZIP·폴더 분석은 프로젝트를 빌드하거나 패키지를 설치·실행하지 않는다. 명세만 있는 경우 선언된 버전의 분석이며 배포 서버에 실제로 설치된 버전의 증명으로 바꾸어 설명하지 않는다. 읽을 수 있는 자료와 Syft cataloger의 지원 범위에 따라 발견되는 구성요소가 달라진다.

## 웹에서 수행하는 업무

1. 고객·사이트와 서버 자산을 등록·수정하고 제품·계약을 연결한다.
2. 자산명·자산번호·모델명·시리얼번호·위치·구매가격·전력·담당자·운영 상태를 관리한다.
3. 자산 목록에서 이름·번호·모델·시리얼·IP·위치·담당자·상태·위험도 조건으로 검색·필터링한다.
4. 소스 ZIP을 첨부하거나 서버 경로를 지정해 분석을 요청한다. SSH 대상에는 정기 분석도 등록할 수 있다.
5. 작업 진행·실패·재시도, 자산·범위별 최신 성공 결과를 확인한다.
6. 자산 상세에서 설치 소프트웨어·SBOM·CVE·EOL·계약·점검 결과와 총합 위험도를 확인한다.
7. 분석·조치·점검·계약 변경을 자산 타임라인으로 확인하고 작업 우선순위를 정한다.
8. 작업목록에서 담당자·기한·상태·심각도별 조치를 찾는다. 이전 SBOM의 미완료 조치도 유지한다.
9. 운영자가 실제 업데이트와 서비스 확인을 수행하고 같은 범위를 재분석한다.
10. 전후 원본과 탐지 변화를 비교하고 담당자·기한·근거·메모·조치 상태를 기록한다.
11. 비교 PDF·JSON을 내려받고 DB·업로드 원본 백업의 복구 검증 결과를 확인한다.

## 재고자산 편의 기능 범위

자산 상세 화면은 다음 정보를 한 화면에 요약한다.

| 구분 | 관리 항목 |
|---|---|
| 식별 | 자산명, 자산번호, 자산 유형, 제조사, 모델명, 시리얼번호 |
| 위치 | 고객사, 사이트, 건물, 층, 전산실, 랙 번호, 랙 위치 |
| 비용·전력 | 구매일, 구매가격, 내용연수, 장부가, 정격/평균 전력, 전력 데이터 출처, 유지·교체 비용 |
| 운영 | IP, MAC, 담당자, 담당 부서, 운영 상태, 서비스 중요도, 마지막·다음 점검일 |
| 보안·수명주기 | 설치 소프트웨어, SBOM 구성요소 수, CVE 심각도별 개수, EOL, 계약 만료, 총합 위험도 |

자산 검색은 서버 측 페이지 조회를 기준으로 구현하고 자산명·자산번호·모델명·시리얼번호·IP·위치·담당자·운영 상태·EOL 임박·위험 등급을 필터로 제공한다. 자산 상세에는 기본 정보, 소프트웨어, SBOM, CVE, EOL·계약, 점검·변경 타임라인 탭을 둔다.

종합 위험도는 CVE 심각도, 지원 종료 임박도, 서비스 중요도, 계약 상태, 최근 점검 상태를 조합한 **EOLWatch 내부 우선순위 점수**다. 산정 근거와 계산 시점을 보존하며 자동 조치 완료나 실제 공격 가능성을 의미하지 않는다.

후속 편의 기능으로 자산 상세 QR 코드, EOL·계약·조치 기한 알림, CSV 일괄 등록, 웹 서버·DB 서버·서비스 관계도, 전력·운영비 집계, 교체 예산과 우선순위 목록을 둔다. 이 기능들은 핵심 자산·SBOM·CVE 흐름을 완성한 뒤 단계적으로 추가한다.

## 판단 기준

- Grype 결과와 OSV 조회는 공개 취약점 정보와의 매칭이다. 실제 악용 가능성은 실행 조건·노출·설정 등 별도 검토가 필요하다.
- OSV 수정 버전은 패키지·현재 버전이 속한 구간을 확인해 산출한다. PyPI PEP440, 명시적 SemVer, npm·Go·Cargo SemVer를 지원하며 지원하지 않는 순서나 Git 그래프는 수정 버전을 추정하지 않는다.
- 전후 비교 상태는 계속 검출·새로 검출·재분석 미검출·구성요소 제거다. 도구·DB·식별 정보 차이는 경고로 보여준다.
- 미검출이 조치 완료를 자동 결정하지 않는다. 운영자가 실제 변경과 서비스 확인 내용을 기록한다.
- 지원 종료 일정은 등록한 날짜와 근거를 보여주며, 각 제품의 최신 공지 전체를 자동 수집한다고 설명하지 않는다.

## 명시적으로 지원하지 않는 범위

컨테이너 이미지·레지스트리 입력, Git URL 자동 복제, 자동 패치, 자동 VEX 완료, 실제 공격 성공 여부의 자동 검증, 공개 다중 고객 서비스의 조직별 데이터 격리는 현재 지원하지 않는다. HBOM·CBOM 생성과 CWE·CCE 중심 분석도 이번 핵심 범위에 포함하지 않는다.

DB·ZIP 백업과 임시 DB 복원 검증은 구현했다. 운영 DB를 교체하는 자동 재해 전환, SSH 키·`.env`·서버 전체 이미지까지 복구하는 기능은 별도 범위다.
