# EOLWatch 현재 범위

코드 기준: 2026-09-21. 기준 문서는 [재시작 계획](RESTART_PLAN.md)이며 이 문서는 그 범위를 요약한다.

## 프로젝트 한 문장

**EOLWatch는 소스 ZIP과 등록 서버의 취약점을 검사하고, CVE 결과·조치·전후 비교를 한곳의 검사 기록으로 관리하는 개발 및 인프라 취약점 검사 솔루션이다.**

Black Duck과 같은 구성요소·취약점 검사 영역에 속하지만, 이번 프로젝트는 두 가지 입력(ZIP, SSH 서버)에서 검사를 시작하고 결과를 기록으로 되돌아보는 흐름에 집중한다. 상용 도구 계정·서버는 필요하지 않다.

## 관리 앱과 검사 대상

- **관리 앱:** React 웹 + FastAPI + PostgreSQL + 검사 worker. 사용자는 브라우저로 작업한다.
- **검사 대상:** 웹에 첨부한 소스 ZIP, 또는 등록된 Linux 서버의 OS 설치 패키지·Python 환경.
- **도구:** Syft 1.51.1로 구성요소 수집, SPDX 2.3 변환, Grype 0.118.0으로 같은 SPDX의 취약점 검사. OSV 교차 검증도 지원한다.
- **실습 환경:** 관리 VM 1대, 대상 VM 2대. 관리 VM 웹은 `127.0.0.1:18080`이며 맥 개발 Docker의 `:8080`은 별도 DB다.

## 세 축과 지원하는 입력

| 축 | 입력 | 읽는 대상 | 비교 범위 |
|---|---|---|---|
| 개발 검사 | 소스 ZIP | 포함된 패키지 명세·잠금 파일·설치 메타데이터 | 서버 + 프로젝트 이름 |
| 인프라 검사 | OS 설치 패키지 | dpkg 설치 패키지 | 서버 + Ubuntu 프로필 |
| 인프라 검사 | 데모 앱 Python | `~/eolwatch-demo/.venv` | 서버 + 데모 프로필 |
| 인프라 검사 (API 전용) | 서버 프로젝트 폴더 / Python 가상환경 | SSH 계정이 읽을 수 있는 절대 경로 | 서버 + 프로필 + 정규화된 경로 |
| 인프라 검사 | SSH 점검 | CPU·메모리·디스크 사용률, 설치 패키지, OS, 서버 정보 | 점검 이력 |
| 검사 기록 | 저장된 검사·SBOM·조치 | DB에 보관된 원본과 이력 | 같은 서버·범위의 이전→이후 |

SPDX 2.3, CycloneDX 1.4~1.7, SPDX+Grype JSON 묶음 반입은 API로만 제공한다. ZIP·폴더 검사는 프로젝트를 빌드하거나 패키지를 설치·실행하지 않는다. 명세만 있는 경우 선언된 버전의 검사이며 배포 서버에 실제로 설치된 버전의 증명으로 바꾸어 설명하지 않는다.

## 웹에서 수행하는 업무

1. `개발 검사`에서 소스 ZIP을 올리고 검사를 시작한다. 진행 상태를 보고 완료되면 CVE 결과를 연다.
2. `인프라 검사`에서 서버 번호·이름·IP·SSH 포트·계정을 등록한다.
3. `SSH 점검`으로 서버 정보를 수집하고 `취약점 검사`로 설치 패키지의 CVE를 검사한다.
4. `검사 기록`에서 서버·범위·날짜·상태로 과거 검사를 찾고 저장된 ZIP을 내려받거나 재검사한다.
5. CVE 결과에서 수정 버전·심각도를 보고 담당자·기한·메모·재검사 근거와 함께 조치를 기록한다.
6. 조치 작업목록에서 담당자·기한 초과·상태·심각도별 업무를 찾는다. 이전 SBOM의 미완료 조치도 유지한다.
7. 의존성 목록에서 구성요소·라이선스·의존관계·원본을 확인한다.
8. 운영자가 실제 업데이트와 서비스 확인을 수행하고 같은 범위를 재검사한다.
9. 전후 검사를 비교하고 PDF·JSON 보고서를 내려받는다.
10. `관리`에서 사용자 권한과 감사 로그를 확인한다.

정기 검사 예약(API)과 DB·업로드 원본 백업의 복구 검증은 추가 서비스·운영 기능이다.

## 판단 기준

- Grype 결과와 OSV 조회는 공개 취약점 정보와의 매칭이다. 실제 악용 가능성은 실행 조건·노출·설정 등 별도 검토가 필요하다.
- OSV 수정 버전은 패키지·현재 버전이 속한 구간을 확인해 산출한다. PyPI PEP440, 명시적 SemVer, npm·Go·Cargo SemVer를 지원하며 지원하지 않는 순서나 Git 그래프는 수정 버전을 추정하지 않는다.
- 전후 비교 상태는 계속 검출·새로 검출·재검사 미검출·구성요소 제거다. 도구·DB·식별 정보 차이는 경고로 보여준다.
- 미검출이 조치 완료를 자동 결정하지 않는다. 운영자가 실제 변경과 서비스 확인 내용을 기록한다.
- 서버 정보(하드웨어·가상화·클라우드·통신)는 설명용이며 취약점 판정에 쓰지 않는다.

## 제거한 범위

2026-09-18에 다음을 코드·DB에서 제거했다. 이 기능들을 현재 기능으로 설명하지 않는다.

- EOL·지원 종료 일정, 공개 EOL 카탈로그(endoflife.date) 조회·적용
- 자산 재고 필드(건물·랙·구매가·전력·보증·담당자·운영 상태·중요도), 위험 점수·우선순위, 자산 PDF·QR·위험도 이력
- 고객·사이트, 제품·계약, 소프트웨어 원장, 수동 SBOM/분석 JSON 가져오기 화면
- Teams 알림, EOL·점검 PDF 보고서, CSV 자산 등록

서버 타임라인(검사·점검·SBOM·조치)과 비교 보고서 PDF/JSON은 남아 있다.

## 명시적으로 지원하지 않는 범위

컨테이너 이미지·레지스트리 입력, Git URL 자동 복제, 자동 패치, 자동 VEX 완료, 실제 공격 성공 여부의 자동 검증, 공개 다중 고객 서비스의 조직별 데이터 격리, 클라우드 계정 API 연동은 현재 지원하지 않는다. 클라우드 리소스 정보는 검사 대상 서버 안에서 읽을 수 있는 메타데이터·DMI로 한정한다.

DB·ZIP 백업과 임시 DB 복원 검증은 구현했다. 운영 DB를 교체하는 자동 재해 전환, SSH 키·`.env`·서버 전체 이미지까지 복구하는 기능은 별도 범위다.
