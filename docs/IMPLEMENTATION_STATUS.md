다음 기능은 코드·라우터·DB 테이블에서 제거했다(마이그레이션 `d2f8c4a71e9b`). 현재 기능으로 설명하지 않는다.

- EOL·지원 종료 일정, 공개 EOL 카탈로그(endoflife.date) 조회·적용, 구성요소 지원 종료일 수정
- 자산 재고 필드(제조사·모델·일련번호·건물·층·랙·구매일·구매가·전력·보증·담당자·운영 상태·중요도), 위험 점수·우선순위, 자산 PDF·QR·위험도 이력, 기한 임박 알림

서버 타임라인과 비교 보고서 PDF/JSON은 유지했다. `product_releases`는 구성요소 식별용 내부 테이블로만 남았다.

## 이전 검증 시점의 실제 시연 증거

서비스: <http://127.0.0.1:18080> — 관리 VM DB. 맥의 <http://127.0.0.1:8080>은 별도 개발 DB다. 아래는 2026-09-15~16 검증 기록이며 당시 메뉴 이름(작업 대상·프로젝트 분석·CVE 조치)으로 수행했다. 저장된 이력 번호는 재범위화 후에도 DB에 남아 있다.

| 검증 | 대상·이력 | 결과 |
|---|---|---|
| 웹에서 OS 검사 | LAB-VM-02, 작업 #1 → 검사 #2 → SBOM #11 | 설치 패키지 669개, Grype 고유 CVE 3,216개·패키지 연결 12,241건 |
| 소스 ZIP 검사 | LAB-VM-01, 작업 #4 → 검사 #5 → SBOM #14 | EOLWatch 소스 구성요소 23개, CVE 9건 |
| 의존성 보완 후 재검사 | 같은 프로젝트, 작업 #10 → 검사 #10 → SBOM #20 | CVE 0건. #5 → #10 비교: 미검출 8, 구성요소 제거 1 |
| 조치 기록 저장 | SBOM #12의 CVE-2025-27516, action #1 | admin 수동 FIXED, 새로고침 후 보존 |
| 비교 보고서 다운로드 | 실제 Chrome, 검사 #5 → #10 | PDF·JSON 다운로드, 오류 없음 |
| 백업·복원 | `/opt/eolwatch/backups/eolwatch-runtime-20260915T151009Z-c9f81ca00e3e` | 당시 23개 테이블 복원 검증, 임시 DB 잔존 0개 |

**CVE 3건 → 0건은 데모 앱 가상환경, 9건 → 0건은 소스 ZIP 범위에 한정된다.** 전체 OS 취약점 해소나 실제 악용 성공·차단의 증명이 아니다. 비교는 과거 CVE의 VEX를 자동 변경하지 않았다. 세부 번호·로그는 [확장 검증 기록](PROJECT_EXPANSION_VERIFICATION.md)에 있다. 그 기록에 있는 제품·계약·EOL 화면 검증은 지금은 제거한 기능의 당시 기록이다.

## 범위와 후속 검증

재범위화 후 아직 브라우저로 끝까지 확인하지 않은 항목: 새 메뉴 구성에서의 개발 검사·인프라 검사 전체 흐름, 실제 서버에서의 서버 정보 카드 표시, ZIP 재검사·실행 중 취소·과거 비교. 순서는 [작업 재개](NEXT_SESSION.md)를 따른다.

현재 범위 밖은 컨테이너 이미지/레지스트리 입력, 자동 패치·자동 조치 완료, 클라우드 계정 API 연동, 공개 다중 고객 SaaS의 조직별 데이터 격리다. 이를 구현했다고 설명하지 않는다. 예약 백업 도구는 기존 서비스 DB를 자동으로 덮어쓰는 재해 전환 도구가 아니다.
