# EOLWatch 요약서 자체 검토와 수정 내역

시스원의 유지관리·공개SW 기술지원 담당자가 발표 설명 없이 읽는다는 기준으로 검토했다. 시스원이 실제로 검토하거나 도입한 자료라는 뜻은 아니다.

| 기존 안의 부족한 점 | 이번 수정 |
|---|---|
| 회사명은 들어갔지만 일반적인 기능 소개에 머물렀다. | 공식 ITO 사업의 시스템통합 유지관리·공개SW 기술지원과 연결하고, 업무 상황별 제공 자료와 담당자의 활용을 표로 정리했다. |
| 본문 세 장이 대상 확인→조치→보고를 반복했다. | 각 장을 업무 활용 / 실제 검증 사례 / 제공물과 적용 전 확인사항으로 구분했다. |
| ‘CVE 3건→0건’만으로는 어떤 환경에서 무엇을 확인했는지 부족했다. | 지정 Python 환경, Jinja2 3.1.4→3.1.6, 원본 웹 비교 화면을 넣었다. 재분석 미검출 3건과 담당자의 수동 완료 기록 1건을 구분했다. |
| 직접 만든 기능과 분석 도구의 역할이 분명하지 않았다. | 자산 연결·조치 이력·재분석 비교·보고서를 직접 구현한 부분으로 밝혔다. Syft·Grype의 역할은 발표자 노트에 설명했다. |
| 기업이 무엇을 받고 적용 전에 무엇을 확인해야 하는지 없었다. | 웹 관리 화면, 조치·비교 자료, 소스 코드·실행·운영 자료와 함께 수집 범위·접근 권한·보관 기준·보고 항목을 제시했다. |
| 짧게 쓰는 데 집중해 근거까지 생략했다. | 문구 반복을 줄인 자리에 실제 화면과 구체적인 결과물을 배치했다. 세부 설명과 출처는 발표자 노트로 옮겼다. |

## 최종 구성

1. 표지: 고객사 자산의 위험을 조치와 보고 근거로 연결하는 서비스
2. 업무 활용: 취약점 공지 / 지원 종료 / 조치 후 고객 보고
3. 실제 검증 사례: 동일 범위 재분석과 담당자 조치 기록
4. 제공물과 적용 전 확인사항: 받을 자료, 로컬 검증 범위, 현장 적용 조건

표지 포함 4장, 본문 3장이다. 기존의 심플한 표지와 베이스 색상은 유지했다.

## 근거와 표현 범위

- 시스원 사업 범위: [공식 ITO 사업 소개](https://www.sysone.co.kr/businesses_veiw.php?idx=6), [공식 전체사업 소개](https://www.sysone.co.kr/businesses.php). 공식 자료는 사업 분야를 확인하는 데만 사용했다. 내부 도구·업무 방식·현재의 문제를 추정하지 않았다.
- 실제 결과: `reports/eolwatch-analysis-3-4.json`, `reports/demo-analysis-comparison.png`, `reports/vulnerability-action-history.png`.
- 구현·검증 범위: `docs/IMPLEMENTATION_STATUS.md`, `docs/NEXT_SESSION.md`, `docs/PROFESSOR_PROJECT_GUIDE.md`.
- 웹 화면은 원본을 삽입하고 PowerPoint의 자르기로 필요한 부분만 표시했다. 화면 내 수치·텍스트는 바꾸지 않았다.
- 미검출은 자동 조치 완료를 의미하지 않는다. 시스원 고객사 운영 환경의 도입 성과나 시간·비용 절감 수치를 주장하지 않는다.
- 지원 종료는 등록한 날짜·근거의 활용으로 설명했다. 공개 EOL 적용 전체 흐름을 실제 검증 완료 사례로 사용하지 않았다.
- 시범 적용의 평가 항목은 자산 식별 정확성, 보고 항목 충족 여부, 점검·자료 작성 시간으로 제안했다. 아직 측정된 효과는 아니다.

## 파일 확인

- 기존 기업 관점 PPT의 해시 보존, 표지와 본문 총 4장, 편집 가능한 글자·도형, 발표자 노트 확인.
- 텍스트 너비·높이 및 슬라이드 밖 개체 검사와 별도 렌더링 미리보기로 배치 확인.
- PowerPoint PDF 내보내기는 앱 응답 시간 초과로 완료하지 못했다. 함께 제공하는 PNG는 별도 렌더링에 의한 구성 미리보기다.
